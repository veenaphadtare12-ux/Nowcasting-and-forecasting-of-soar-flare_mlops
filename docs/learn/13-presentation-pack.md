# Lesson 13 — Presenting results honestly: a facts sheet with sources, and slide-ready figures

## What we built

`docs/PRESENTATION_FACTS.md`: every number for the project review, each followed by the output file it came from.
It's generated by code (`python -m src.presentation_facts facts`), not typed by hand. We also built two slide figures
in `docs/presentation_figures/` at 1920×1080 with large fonts and a fixed colour code: SoLEXS orange, HEL1OS blue,
everything else grey.

## Why it matters

In a review, the worst moment is "where does this number come from?" followed by silence. A facts sheet where every
number carries its source is like a bibliography for your results: anyone can check it, and you can't accidentally
present a stale number. Generating it by code means that if the pipeline re-runs, the sheet is regenerated with the
new values, not a mix of old and new.

## Concepts

**Single source of truth.** Numbers live in output files (`reports/*.json`, `data/processed/*.csv`). Documents
*read* them; they never retype them.

**Provenance.** Knowing where each number came from: the file, the period and the definition (for example "GOES flares
peaking while SoLEXS had valid data" vs "all GOES flares").

**Honest framing.** Show baselines next to models, intervals next to means, and say plainly when a sample is too small.
"We cannot conclude" is a valid, professional result.

**Slide figures differ from analysis figures.**
- Larger fonts: they're read from the back of a room.
- No titles inside the image: the slide title says the message.
- Fixed size: 16:9 at 1920×1080.
- Consistent colour meaning across slides: orange always means SoLEXS.

**Test-period discipline continues.** The pack shows the test period only as counts (rows, days, sessions), never statistics.

## Tools used

| Tool | What it is | What it did here | Most useful commands |
|---|---|---|---|
| **Python + pandas/json** | Readers for output files | Built every section of the facts sheet | `python -m src.presentation_facts facts` |
| **matplotlib** | Plotting | 1920×1080 figures (`figsize=(19.2, 10.8)`, `dpi=100`, no `bbox_inches="tight"`) | `python -m src.presentation_figures` |

## Break it on purpose

Make a stale number appear, then fix it the right way.

1. Open `docs/PRESENTATION_FACTS.md` and change the nowcast TSS in section I by hand (for example to 0.80).
2. Ask yourself: what now disagrees? (`reports/model_metrics.json` still says 0.727.) That's exactly how hand-edited
   decks go wrong.
3. Undo by regenerating: `python -m src.presentation_facts facts`. The value is back to the file's number.
