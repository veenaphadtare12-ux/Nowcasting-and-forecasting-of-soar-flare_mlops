# Security

Checked on 2026-11-14 (v1.1.0). Scans run on every push in the CI job `security`.

## Controls
| Area | Control | Where | Proof |
|---|---|---|---|
| Authentication | `X-API-Key` on `POST /predict`; keys from `FLARE_API_KEYS` (comma list for rotation); no key configured = every call refused | `src/serving/security.py` | `tests/test_api.py::test_predict_needs_a_valid_api_key`, `test_predict_fails_closed_without_configured_keys`; smoke test "POST /predict without key → 401" |
| Abuse | sliding one-minute rate limit: 300/min per anonymous IP, 6000/min per valid key, 429 + `Retry-After`; `/health`, `/metrics` exempt | same | `test_rate_limit_returns_429_and_spares_health`; k6 at 200 users: 3,055 × 429 from one key |
| Input size | bodies > 4 MB refused (413) in the API; nginx `client_max_body_size 4m`; Caddy `request_body max_size 4MB` | API, `docker/nginx.conf`, `docker/caddy/Caddyfile` | `test_large_bodies_are_refused` |
| Browser | CORS allow-list, wildcards ignored; `X-Content-Type-Options`, `X-Frame-Options DENY`, `Referrer-Policy`, `Permissions-Policy`; `Server` header removed | API, nginx, Caddy | `test_cors_allow_list_never_wildcards`; `curl -I http://localhost/` |
| Transport | Caddy: automatic HTTPS (Let's Encrypt) when `SITE_ADDRESS` is a domain, HTTP→HTTPS 308 | `docker/caddy/Caddyfile` | local-CA run on 2026-11-14 (`docs/PRODUCTION_READINESS.md`) |
| Exposure | only Caddy listens publicly (80/443); every other Compose port bound to 127.0.0.1; `/api/metrics` blocked at nginx; Grafana, Prometheus, Prefect, MLflow, Alertmanager internal in Kubernetes | `docker-compose.yml`, `docker/nginx.conf`, `k8s/overlays/prod` | `scripts/k8s/smoke.sh` "metrics not public" |
| Secrets | only in GitHub Actions secrets or the git-ignored `.env`; Kubernetes Secrets created at deploy time; CD sends them over SSH on stdin, never as command-line arguments; the local API key is generated by `up.ps1` and never printed | `.gitignore`, `scripts/k8s/deploy.sh`, `.github/workflows/cd.yml` | `git grep` finds no key; `.env` is ignored |
| Containers | non-root (api/worker 10001, frontend 101, grafana 472, prometheus/alertmanager nobody); `no-new-privileges`; `cap_drop: ALL` (Caddy keeps only `NET_BIND_SERVICE`); memory/CPU limits; healthchecks; restart policies; logs rotated; exact image versions | `docker-compose.yml`, `k8s/base` | `docker inspect` output in `docs/PRODUCTION_READINESS.md` |
| Fault injection | `FLARE_FAULT_INJECT_RATE` (alert drills) is off by default, ignored in production, never on `/health`/`/metrics` | `src/serving/api.py` | `test_fault_injection_is_off_by_default_and_counted_when_on` |

## Accepted risks
| Risk | Why accepted | Mitigation | Plan |
|---|---|---|---|
| MLflow 3.16.1: CVE-2026-53995, CVE-2026-115886, CVE-2026-116691 (fixed in 3.17.x) | MLflow is not in the API image. The MLflow server is internal only (127.0.0.1 in Compose, ClusterIP in Kubernetes) and the API only reads it. Upgrading needs a registry schema migration and a new 1.3 GB server image; the frozen registry was built with 3.16.1 | not reachable from the internet; anonymous users cannot reach it | upgrade server image and `requirements-ci.txt` to ≥ 3.17.2 together, run `mlflow db upgrade` on a backup first |
| Caddy, Prefect server and MLflow containers run as root (upstream images) | their volumes are root-owned; changing it needs custom images | `no-new-privileges`, all capabilities dropped (Caddy keeps `NET_BIND_SERVICE`), not public except Caddy | custom non-root images if the server becomes multi-tenant |
| Rate limit is per process | the API runs one uvicorn worker per container (Prometheus counters would split across workers); in Kubernetes each of the 2 replicas counts separately | per-key budget is generous; Caddy/Ingress can add a global limit | Redis-backed limiter if more replicas are needed |
| Grafana anonymous Viewer | read-only dashboards, internal only | admin password from a Secret / `.env` | disable anonymous access if Grafana is ever published |
| SSH from GitHub-hosted runners | runners use changing IPs, so port 22 must accept the internet | key-only login for the `deploy` user | self-hosted runner or a VPN to close port 22 |

## Rotating the API key
See `docs/RUNBOOK.md#rotate-the-api-key`. In short: add the new key next to the old one, deploy, switch clients, remove
the old key, deploy again. Both keys work during the switch, so there is no downtime.
